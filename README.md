# CQA Platform — оценка качества диалогов (Freedom Broker hackathon)made by "Semipalatinck Victims" team

Node.js + Express + SQLite, интерфейс на чистых HTML/CSS/JS (один компонент `#cqa-root`, без сборки и зависимостей — его можно подключить как HTML-ресурс Dynamics 365; адрес сервиса задаётся `window.CQA_API_BASE`).

## Запуск
1. Node.js 20+. В папке проекта: `npm install`
2. Добавьте `OPENAI_API_KEY` в `.env` — он используется для оценки диалогов и распознавания аудио через Whisper.
3. Модель оценки задаётся через `OPENAI_MODEL` (по умолчанию `gpt-4.1-mini`). При необходимости вместо OpenAI для оценки можно задать отдельный `OPENROUTER_API_KEY`.
4. Whisper принимает аудиофайл до 25 МБ.
5. В `.env` проверьте `DATASET_API_URL` (ссылка GET для DEV; для контрольного набора организаторы дадут другой group_id — можно заменить ссылку и снова нажать «Загрузить данные»).
6. `npm start` → http://localhost:3000 → **«Загрузить данные из API»**.
7. «Оценить неоценённые» (пакетно, 3 параллельных запроса) или откройте диалог и нажмите «Оценить».

Не коммитьте `.env` и ключ в открытый репозиторий (`.env` уже в `.gitignore`; для жюри есть `.env.example`).

## Что умеет
**Контур 1 — оценка**
- Чек-лист организаторов (8 критериев, секции, веса, шкалы, N/A) — начальная конфигурация v1.
- Редактор: добавление/удаление/порядок критериев, секции, формулировка, тип (Да/Нет, шкала со ступенями и описаниями, грубое нарушение), вес, N/A + условие N/A, общие правила. «Сохранить как новую версию» → она становится активной и применяется к следующим оценкам; старые оценки хранят снимок своего чек-листа. Версию можно выбрать при оценке конкретного диалога.
- Оценка через OpenAI (RU / KZ / EN; реплики бота и системные события — контекст; можно отдельно настроить OpenRouter). Модель возвращает ответ, уверенность, объяснение, **номер реплики-доказательства и дословную цитату**; сервер проверяет цитату по транскрипту. Для пропущенного действия показывается проверенный участок (#реплики, время), для N/A — причина.
- Идентификация, все критерии N/A и грубые нарушения проходят отдельный короткий «слепой» повторный проход той же модели: второй запрос не видит первоначальные решения. Расхождение, низкая уверенность или непроверяемое доказательство помечаются для проверки человеком; балл автоматически не подменяется. Это снижает риск ошибки, но не гарантирует объективность — ИИ не заменяет проверяющего.
- Расчёт на сервере (`src/scoring.js`): «Да» = вес, шкала = ступень / макс. ступень × вес, N/A исключается и вес перераспределяется (максимум 100), округление до 2 знаков, нет применимых критериев → итог не рассчитывается, грубая ошибка — отдельный флаг. Показываются баллы по критериям (после перераспределения) и по секциям.

**Контур 2 — работа с результатом**
- Карточка: транскрипт + результат. Клик по доказательству прокручивает к реплике и подсвечивает её; в звонке ещё и перематывает запись на это место и запускает воспроизведение.
- **Аудио**: ссылки организаторов подписаны и не отдают CORS/Range, поэтому сервер скачивает запись, кэширует её в `data/audio/` и отдаёт через `/api/conversations/:id/audio` с поддержкой перемотки (также понимает ответ в виде JSON+base64). В карточке любого диалога можно загрузить или заменить аудио. Новая запись сначала распознаётся через Whisper и превращается в транскрипт с временными метками; только после этого доступна оценка. Реплики аудио не разделяются по голосам автоматически, поэтому ИИ определяет роль по контексту и содержанию. Плеер поддерживает скорость, ±10 с, подсветку текущей реплики и перемотку по репликам.
- Апелляция: критерий + комментарий → вкладка «Апелляции»: проверяющий видит спорную оценку, комментарий и фрагмент диалога, подтверждает или меняет значение (Да/Нет/N/A/ступень), обязательно указывает причину; итог пересчитывается. В карточке: оценка ИИ → решение → итог «было → стало».
- Вкладка «Аналитика» использует Chart.js из `public/Chart.js-master/Chart.js-master`: столбчатый график средних баллов по критериям (самый слабый выделен), гистограмму итоговых оценок и радар по секциям чек-листа. Карточки показывают число оценённых диалогов, средний балл, грубые ошибки и апелляции. Фильтры канала и языка перестраивают все графики; доступна также разбивка по операторам, если источник передаёт их идентификаторы.
- В блоке экспорта выберите DEV или PROD, укажите название команды и нажмите «Экспорт results.json». Проверяются точное число записей (65/10), уникальность исходных conversation_id, все 8 кодов критериев, типы значений и согласованность итогового балла. Неоценённые/некорректные записи включаются как `status: "error"` с причиной, а не теряются. Скачанный файл положите в `results/dev/results.json` или `results/prod/results.json`. Для загрузки PROD нажмите «Загрузить PROD» и введите group_id от организаторов.
- В списке диалогов кнопка «Сбросить результаты» удаляет оценки и все связанные апелляции после подтверждения; сами диалоги, аудио и версии чек-листа остаются.

## Примечания
- **Время в звонках.** Метки звонка — ISO; время относительно записи считается от системной отметки «запись запущена» (если речь началась раньше — от первой реплики). Если реплики «не попадают» в звук, подправьте поле «Сдвиг, с» у плеера (запоминается для диалога).
- **Стоимость.** Для оценки через OpenAI используется `gpt-4.1-mini`; модель меняется через `OPENAI_MODEL` в `.env`. Для оценки через отдельный OpenRouter-ключ используйте `OPENROUTER_MODEL`.
- Оценка ИИ предварительная — спорные случаи решаются через апелляцию. Дикция/интонация не оцениваются (в чек-листе таких критериев нет; для них нужен анализ звука).
- Старый файл `data/cqa.db` совместим (миграции автоматические); оценки старого формата помечаются «Переоценить».
